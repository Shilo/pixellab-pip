# VFX Workbench Routing Research

Last reviewed: 2026-10-15 (public REST route status; live test: 2026-10-11).

This is a limited live test of PixelLab MCP `vfx_workbench`, with matched raw-image animation and static-image baselines. It establishes practical routing boundaries, not a universal quality guarantee. The 0.4.130 announcement also says VFX is available through API, but current public REST v2 docs do not publish a route or schema; this research uses the documented MCP contract and does not infer a REST endpoint. Public docs also do not prove that MCP Workbench and the experimental Create VFX website page share an implementation.

## Use-Case Matrix

| Request | Default route | Conditional route | Avoid |
|---|---|---|---|
| Hit, burst, or explosion with readable onset, peak, and decay | VFX Workbench preset, then tune timing or add a part. `impact_burst` produced a 64×64 six-frame one-shot at 16 fps after correcting its dead tail. | Static Create Image Pro when the user asks for a still effect; raw animation when an existing effect image needs unconstrained motion. | Treating frame-count changes alone as sufficient: retiming the burst left two blank frames until its active part was extended. |
| Spell, cast, level-up, or looping aura | VFX Workbench; use separate parts for staged phases or behind/front sprite layering. The aura preset made a clean 8-frame loop at 12 fps around a managed character. | Use raw animation for free-form motion on an existing image when composition controls are unnecessary. | Promising pixel-exact sprite preservation: foreground particles can overlap source pixels. |
| Projectile with a named trajectory, trail, or impact | VFX Workbench `throw` with a separate projectile input; one call composed projectile, trail, and impact roles. | Raw animation for unconstrained motion of a supplied projectile image when independently addressable parts are not needed. | Passing a whole spritesheet as a URL when its frames/timing must be preserved; the tested sheet URL was treated as a single still. |
| Rain, smoke, or other repeatable ambient effect | VFX Workbench loop. `rain_streaks` amount changed canvas fill from about 3% to 5–6%; a `smoke_column` loop accepted measured amount/height settings. | Static generation for an atmospheric still or background. | Guessing parameter names/ranges: unsupported `speed` and out-of-range `height` were rejected; use live help and returned limits. |
| Effect attached to a character or sprite | VFX Workbench `--sprite`, using a managed `character:<id>:<direction>` or native workbench image ID when available. PixelLab positioned the subject and exposed behind/front clips. | Static edit route for a still composite; raw animation if the source image itself is the motion target and no effect parts are needed. | Using the edit target role for an animated composition, or assuming every foreground overlay leaves source pixels unchanged. |
| Reusable effect-only animation or component clips | VFX Workbench on a standalone canvas; use normal export for full playback and `--game-pack` for component sheets/metadata. | Create Image Pro for a reusable still; an isolated part can be selected in the game-pack ZIP. | Assuming `--part` makes the ordinary GIF/PNG/JSON part-only: those remained the complete effect in testing. |
| Still effect or static add-on | Create Image Pro for an isolated effect; image edit for a still added to a supplied target. The matched Pro request returned 16 transparent 64×64 candidates. | VFX Workbench only if the intended result is animated. | VFX Workbench for a static-only request. |
| Existing effect image with loose/free-form motion | Raw `animate_image`; use `animate_image_pixminimax` when explicitly requested. Both matched routes made a readable expanding ring in a 64×64 four-frame test. | VFX Workbench when the user needs staged parts, trajectory, or a component export rather than generative whole-frame motion. | Expecting raw animation to provide independently editable layers or game-pack part metadata. |

## Measured Boundaries

- Low and high Workbench modes returned the same preset/recipe in the tested pair; high added review prose. Low is the normal default.
- Mutations/rendering returned new step IDs. A patched child changed the aura spark count; re-rendering the earlier step preserved its original recipe and sprite alignment.
- A managed character ID aligned the subject's visible feet; a PixelArt Workbench image ID retained its six-frame timing. A URL or base64 image works as a single still; a URL to a 192×128 exported sheet lost its six-frame interpretation.
- The normal export provides full-effect GIF, spritesheet PNG, and JSON. Game-pack ZIPs include component sheets and their runtime placement/timing manifest. `--part` was isolated in the ZIP while normal outputs remained full-effect.
- The raw-animation comparison returned the source plus four generated frames. `animate_image` changed one visible pixel in its first returned image; PixMiniMax preserved the first image exactly and ended on a fully transparent frame. PixelLab did not report frame timing, so local preview GIF timing was a presentation choice. This is one small matched sequence per route, not a broad quality ranking.
- One projectile game-pack GIF was read as 12 frames by ffmpeg and PixelArt Workbench; Pillow raised a decompression-bomb error while reading it, and the raw bytes contain a secondary GIF header. Validate outputs with the target engine/decoder and use the PNG/JSON game-pack data for engine integration. This is a single observed interoperability issue, not a general claim about all exports.

## Coverage Checklist

- **Use-case families:** two cases each for burst/hit/explosion (`impact_burst`; explosion plus smoke linger), spell/aura/status (managed aura; staged charge-up into level-up), projectile/trail (traveling `magic_orb`; supplied spear with `throw`), weather/environment (rain density variants; smoke amount/height), and sprite attachment (34×54 user sprite; 48×48 managed character). Standalone transparent effects and sprite-composition previews were both checked; isolated `smoke_puff` export was checked inside a game-pack.
- **Command contract:** start/help and read-only part/preset inspection; add, set, remove, render, throw, and export. Tested low/high notes behavior, valid/invalid controls, new IDs after mutations, immutable branches, and replay with fresh IDs. Palette-lock behavior was not isolated, so exact palette matching remains unverified.
- **Inputs and outputs:** tested a PixelArt Workbench image ID, managed `character:<id>:south`, base64 PNG, and HTTPS PNG/spritesheet URL. Verified normal GIF/PNG/JSON, game-pack ZIP, and isolated-part ZIP semantics. Static URL images were accepted; local file paths were not tested.
- **Alternatives:** matched one static Create Image Pro effect to raw `animate_image` and `animate_image_pixminimax` runs. The raw comparison is one four-frame sample per route, not a ranking. Managed object animation was not compared because these tests did not use an existing managed object or object-animation lifecycle.
- **Visual/output checks:** inspected representative full playback and first/peak/last frames at native scale and enlarged view; checked source placement/overlap, bounds and warnings, loop behavior, frame count/timing, transparency, GIF decoding, spritesheet cell geometry, JSON frame metadata, ZIP integrity, and component contents. The aura pixel comparison found 923–941 of 944 source-visible pixels unchanged per frame; foreground spark overlap accounts for the changed pixels. This does not establish a general exact-preservation guarantee.

## Cost and Evidence

The current live `describe start` help says no generation is charged; public MCP docs describe VFX Workbench as free for subscribers. An eligible subscriber's isolated start/export calibration showed no balance change, but VFX calls exposed no per-call usage. Keep those statements distinct; the tool did not return a per-call charge receipt. The paid matched comparators used 12 generations with direct charged receipts (Create Image Pro 10; raw animation 1 each); a managed fixture tool response reported 2 generations without a `usage.generations` or `charged` receipt. Total accounted spending was 14 of the authorized 2,000-unit cap. The 14 comprises 12 receipt-confirmed charges plus the fixture tool's 2-generation report.
