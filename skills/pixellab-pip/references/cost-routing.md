# Cost Routing

Read this when the user says cheap, affordable, low-cost, budget, minimize credits, avoid Pro, or asks for a cost-driven Pro-vs-cheap comparison. For normal route selection, use `SKILL.md` and the matching asset reference; a Pro/new/v3 label alone does not require this file.

The rule: satisfy the asset intent with the lowest documented-cost route likely to work, then report the tradeoff. Do not silently upgrade to Pro. Cheap mode also changes retry behavior: a first approved generation is not permission for open-ended paid iteration — before each additional paid attempt (prompt tweak, rerun, extra candidate, Pro comparison, retry after failure, batch expansion, or switch to a paid edit route), ask and include the route, expected cost category, and cost already spent, unless the run's approved retry allowance in `auto.md` → Bounded plans and resuming covers it. Free/local work (polling, downloads, cropping, assembly, packaging, manifests, verification) never needs permission.

Label semantics (`Pro` expensive; `v3`/`new`/Pixen/PixFlux/BitForge cheap-family hints; `inpaint-v3` is Pro despite the suffix; see SKILL.md Model And Mode Terms). Route by the concrete endpoint, not the label. Pro Flash is a separate family with operation-specific pricing; read `pro-flash.md` before comparing it. Inline `enhance_prompt` fields whose OpenAPI documents the surcharge add about 0.05 generations. Standalone enhancer endpoints have route-specific USD estimates; a prior live check observed 0.05 generations only for `enhance-pixen-prompt`. Treat prompt enhancement as extra cost, and skip it when the user wants cheapest-possible output unless prompt-quality risk is high and you name the cost. PixMiniMax is a separate paid animation route, not a cheap-family synonym for v3.

## Current Cost Findings

Core cost facts checked against the refreshed official REST v2 OpenAPI and MCP docs on 2026-11-06 (UTC), plus the Version 0.4.128 announcement. PixelLab states Pro Tools cost 10 generations for 16×16–256×256, 15 for 256×256–384×384, and 25 for 384×384–512×512. The announcement overlaps at 256 and 384; MCP now states the edges (inpaint and Create Image Pro sheets): 10 up to 256×256, 15 up to 341×341, 25 above for square canvases. Non-square prices are aspect-adjusted, not based on the longest side. Route-specific sheets, rotations and states below override these general bands. Check returned usage. Managed PixMiniMax fields and examples remain from the 2026-10-05 documentation refresh:

- `create-character-v3` / MCP `create_character(mode="v3")`: `max(1, ceil(width * height * 8 / 65536))` generations when rotating a reference at its own dimensions; `1 + ceil(s * s * 8 / 65536)` from scratch (s = max dimension). A 48×80 or 32×256 reference is 1 generation; setting MCP `size` makes the output square and changes that estimate. Supplying all directions is a 0.25-generation import. MCP character Pro uses a 3×3 sheet: 10 through 85px, 15 at 86–113, 25 at 114–128; its 128px input cap differs from REST Pro's 168px schema. Standard's documented 1-generation charge for 4/8 directions is a price fact, not a recommendation; its restricted routing policy is in SKILL.md → Model And Mode Terms.
- MCP `create_character_state`: one 10/15/25-generation charge covers all source directions. The art bounds are squared, padded 20%, and floored at 32px; that cell costs 10 through 84px, 15 at 85–112, 25 above. Source frames through 70px always cost 10 and through 93px cost at most 15. With `override_width`/`override_height`, price the enlarged frame directly at those thresholds (48→128px can change 10 to 25). Otherwise large-frame art occupancy may be unknown; reserve up to 25, as submission checks only the 10 floor. REST `create-character-state` has its own schema and USD estimates; do not infer a per-direction charge.
- Character template animation: nominally 1 generation per direction up to about 92px, then billed per rendering batch. MCP examples qualify the 96px case: clips up to 8 frames cost 1; 9-frame jumps and 10-frame backflips usually cost 1, or 2 when the character fills the full 96px box. At 128px, breathing-idle costs 1 and walking 2; the longest clips set higher ceilings (for example, jumping-1 costs 3 at 128px, 5 at 180px, and 9 at 256px). MCP says the submit receipt gives the exact ceiling; check returned usage. Managed Pro animation for characters or objects: 10, 15, or 25 per direction by canvas/image size (80–200 for a full 8-direction run). MCP `animate_object(mode="pro")` is available and requires its documented confirmation gate; the current MCP `animate_character` mode list has no `pro`. v3 custom animation is size-and-frame-scaled on the generated canvas: `ceil(width * height * frame_count / 65536)` per direction. Silhouettes may expand beyond the source image, so inspect the returned dimensions and usage instead of estimating from source size. For cheap custom animation, compare v3 with PixMiniMax using the documented size/frame costs below; the ordinary engine default is in `animation.md` → Route Choice.
- Skeleton v3 is a separate paid beta route. The refreshed REST and MCP descriptions no longer state a Tier 1 gate. MCP docs price raw `animate_with_skeleton_v3` and managed-character `skeleton-v3` at 2 generations for 3 frames, 3 for 4–14, and 4 for 15, per direction for managed animation. The MCP custom-motion instruction call is free; REST action-text submission is a generation request (surface contracts in `preset-skeleton-template-animation.md`). Check returned usage for the exact charge. Current public USD estimates for the raw endpoint are about `$0.0436`/3 frames, `$0.0513`/8, and `$0.0622`/15.
- MCP `create_1_direction_object`: whole candidate sheet, not per candidate; 10 generations for size 16–32, 43–64, 86–128, 171–256; 15 for 33–42, 65–85, 129–170. The 25 band is unreachable. `create_8_direction_object` instead follows the longest frame side: 10 through 84px, 15 at 85–112, 25 at 113–168; 168px is its hard cap. REST counterparts retain route-specific USD estimates.
- MCP `create_object_state`: one charge covers all source directions. Eight-direction text edits cost 10/15/25 at longest-side thresholds 84/112px; one-direction or reference-image states instead use the frame's aspect-adjusted canvas bands (square thresholds 256/341px). The current MCP state signature does not expose a reference-image field; do not invent one from this pricing prose. Read the source dimensions and visible edit path before quoting.
- Map objects (`create_map_object` / `POST /map-objects`): documented separately from object Pro Tools; cost is not labeled — report or measure it rather than assuming.
- MCP `create_ui_asset` documents 10 generations up to 256×256, 15 up to 341×341, and 25 above. Non-square UI uses aspect-adjusted bands: 16:9 costs 10 up to 341×192, 15 up to 456×256, and 25 from width 457. There is no UI quote endpoint; check returned usage rather than applying the longest-side rule. REST `create-ui-asset` is Pro but does not publish these generation-unit bands.
- Pro-labeled REST routes include `generate-image-v2`, `generate-with-style-v2`, `generate-ui-v2`, `image-to-pixelart-pro`, `edit-animation-v2`, `interpolation-v2`, `transfer-outfit-v2`, `inpaint-v3`, `edit-images-v2`, and `generate-8-rotations-v2`. Use the announced 10/15/25 bands for Pro Tools billed by image size; frame- and direction-based routes retain their documented route-specific billing. MCP `edit_image` and `inpaint_image` are the same Pro routes as REST `edit-images-v2`/`inpaint-v3` (confirmed by field-level schema match, not base `edit-image`/`inpaint`), and MCP `create_image_pro` maps to `generate-image-v2`; MCP bills `create_image_pro` by its whole candidate sheet, not the canvas (see `create-image-pro.md`).
- MCP `edit_image` and `inpaint_image` document 10/15/25 generation bands with the same square edges and aspect adjustment as UI above. Inpaint examples are 360×168 = 10 and 168×360 = 15, so orientation matters. `edit_image` bills multiple-frame inputs by the whole grid, not per frame; its REST counterpart is `edit-images-v2`. Check returned usage.
- Pro Flash prices and free exact-size checks are canonical in `pro-flash.md`; read it before comparing creation, rotations, edit/inpaint, reuse, or conversion totals. Visual quality remains operation-specific and must be verified.
- Cheap edit and convert: `edit_image_pixen`/`edit-image-pixen` and `image_to_pixelart`/`image-to-pixelart` cost 1 generation. The cleanup family — `unzoom_image`, `correct_pixelart`, `reduce_colors` and their REST twins — costs 0.1 generations per call. `correct_pixelart` and `reduce_colors` take several same-size frames per call, so batch rather than loop; `unzoom_image` is one image per call.
- Normal-map generation (`create_normal_map` / `POST /normal-map`) costs 0.1 generation in the default `lite` mode and 0.5 in `pro`. See [Normal Maps](normal-maps.md) for delivery and per-call billing details.
- Tilesets: MCP documents standard `create_topdown_tileset` and `create_sidescroller_tileset` at 1 generation now that standard runs on Pixen (the model it replaced billed 1–4 and 2–3). `mode="pro"` costs 15 generations through 32px, or 25 above. MCP sidescroller still permits only 16/32px tiles despite its price prose mentioning larger tiles; do not infer a new size. Both MCP Pro routes and REST top-down Pro require Tier 1+ (not a trial). Failed jobs are not charged. REST documents no tileset price; check returned usage there.
- MCP `create_building_kit` costs 10 generations for `layout="materials"` at all sizes; `layout="grid"` costs 10/15/25 as its projection and drawn sheet grow. Isometric defaults to grid, while square-topdown and oblique default to materials. Exact bands and the separate 15/25-generation reserve are in `tileset.md`.
- MCP `create_tiles_pro`: price the full sheet of cells as drawn, including geometry/view/depth/height. Independent tiles cost 10 or 15, never 25; most 16–48px shapes cost 10, 64px top-down costs 15, and 80px+ usually costs 15. Oblique cells can reach 15 sooner; very flat cells can stay cheaper. Style mode prices the style image's dimensions. Fewer numbered descriptions do not shrink the sheet or price. Connectable tilesets can reach 25 at 96px+. Submit reserves (15, or 25 at 112–128px) are not actual charges.
- MCP `create_path_tiles`: 10–25 by the full sheet and angle. Square-topdown takes 32px: default angle 15, straight-down 25, near-side 10. Isometric 48px costs 10; 64px usually 10 (15 straight-down); 96px usually 25 except near-side. Preserve requested projection/size; never flatten art just to lower cost.
- Non-Pro-labeled image routes: MCP `create_image_pixen` and `create_image_pixflux` each cost 1 generation; their REST counterparts are `create-image-pixen` and `create-image-pixflux` (`-background` is a second URL for the identical PixFlux schema, same tier). `create-image-bitforge` is REST-only with no MCP tool. `animate-with-text-v3`/MCP `animate_image` (documented cost `ceil(width * height * frame_count / 65536)` generations) and `generate-8-rotations-v3` are the cheap v3 animation/rotation family.
- PixMiniMax (raw `POST /animate-pixminimax` / MCP `animate_image_pixminimax`, and managed REST `/animate-character` or `/characters/animations` / MCP `animate_character(mode="pixminimax")`) is priced by generation time. Raw-route examples include `32x32`/4 frames = 1 generation; `64x64`/4, 8, 16, and 40 frames = 1, 1, 2, and 6; and `80x80`/8 = 1. The managed-mode description specifically confirms `64x64`/8 = 1 and /40 = 6 generations per direction; multiply by the requested direction count. The MCP raw-route docs explain the steps: the price follows an upscaled canvas (×4 up to 64px, ×2 up to 128px, ×1 above, by the longer side), so 64, 128, and 256 price the same — 4–8 frames = 1, 12–16 = 2, 20–24 = 3, 28 = 4, 32–36 = 5, 40 = 6 — and a canvas just above a step is cheaper on long clips (40 frames: 6 at 128×128, 2 at 132×132), as is splitting one long clip into several short ones. In cheap mode, propose such a size or split; never change the user's canvas or clip silently. Both routes accept 4–40 generated frames in multiples of four; the raw input is capped at 256×256, while managed mode uses the stored character size (the public description says “any size”). Use returned `usage.generations` for the actual charge; website USD estimates are a separate reporting unit. Do not call or document the unversioned/private cost route mentioned in descriptive text.
- REST `POST /image-to-text` returns a generic image description or custom visual answer as text, not an image. PixelLab estimates about 0.09 generations for a typical sprite or screenshot; longer answers cost more. See the SKILL.md Intent Router for when to use it. The actual usage is returned in the response.
- `frame_count` is a documented cost driver for both v3 and PixMiniMax, but their pricing rules differ. Use the v3 area formula only for v3; for PixMiniMax use the published examples or returned usage. Change documented cost drivers instead of guessing: route family, mode, direction count, candidate count, enhancement use, size, and frame count where the selected route documents it.
- Talking portraits: portrait attachment, talking GIF rendering, and lip-sync plans are free; vocal generation is the paid step. MCP `create_vocal_animation` now prices passes × portrait size: 2 passes for 3 positions, 3 for 5/7, 4 for 12; per pass 1 through 64px, 2 at 96–128, 4 at 160, 5 at 192, 8 at 256. Default 7 positions costs 3 at 64px, 6 at 128, 24 at 256. Extra fill passes may increase the quote; the documented ceiling is 40 generations. Quote the receipt, not only the base calculation; REST publishes no matching generation-unit schedule. Generate one mood per approved call.
- MCP rooms: eligibility and painting/cutout prices are in `scenes-and-backgrounds.md`. Existing map arrangement/read operations are free; generating their source art remains paid. Cancellation billing differs by surface; see `job-lifecycle.md` before promising savings.
- VFX Workbench live MCP help says no generation is charged; public docs describe it as free for subscribers. Confirm account eligibility; if a call omits usage, report it as not exposed rather than inferring a per-call amount. REST `POST /vfx` is paid: `lite` from 1 generation, `pro` from 6 for a new effect (4 for a change), charged on delivery at up to 2× the quote. See [VFX Workbench](vfx-workbench.md) for both.
- REST font generation documents fixed pricing of 15 subscription generations, or at least `$0.115` in credits. MCP `create_font` documents the same fixed price. The former `image_size` pricing tier has been removed.

If exact current costs matter, use documented free quotes when available or refresh the selected route's pricing. A submit receipt starts paid work; never submit just to discover a price. A balance-before/after test needs explicit approval. Do not invent prices for routes whose docs only show a label.

## Cheap Route Preferences

| Asset | Cheap default | Use Pro only when |
|---|---|---|
| General images | `create-image-pixen`/`create_image_pixen` (small/single/icon iteration, outline/detail/view controls) or `create-image-pixflux`/`create_image_pixflux` (general/background style) | Style-reference generation or high-quality sheet output is required and approved |
| Icon sheets | Compare single-image calls plus approved assembly with a sheet call, preserving the requested subjects/count (`icon.md`) | User approves the Pro sheet after the tradeoff is named |
| Characters | v3 for ordinary humanoids; reuse a suitable supplied sprite through v3. For text-only quadrupeds use Pro Flash (`pro-flash.md`). Compare suitable modern routes by usable output and total approved cost, not nominal call price | Its controls fit the request and the user approves the size-based cost above |
| Character animation | Compare fitting template, v3, and PixMiniMax costs; explain any engine/motion tradeoff from `animation.md` before selecting the cheapest suitable route; one direction first | User approves Pro cost |
| Objects | For standalone visuals that don't need managed object IDs: a general-image/Pixen/PixFlux or isometric-tile route, labeled as not creating a managed object; map-object route when a map object is specifically needed (measure cost) | User accepts the selected object/candidate-sheet price above |
| Object animation | `mode='v3'` (documented default) | User explicitly approves Pro |
| UI | Non-Pro general-image route for loose UI images (explain weaker structure); `generate-ui-v2` only if its cost is acceptable | Structured `create_ui_asset`/`create-ui-asset` is required and approved |
| Image-to-pixel-art | `image-to-pixelart`/`image_to_pixelart` (1 generation) for fixed supported sizes | No-size auto-detection: older REST Pro uses the announced size bands; Pro Flash is a documented same-conversion alternative at 6 generations when explicitly requested |
| Edit | MCP `edit_image_pixen` (1 generation) when the source is ≤256px per side and the target area ≤256×256; otherwise base `edit-image` via REST. MCP `edit_image` is Pro-tier (`edit-images-v2`) | Larger canvas, multi-image batch, or reference-mode edit is required and Pro cost accepted |
| Inpaint | Compare REST base `inpaint` controls/cost with MCP/REST Pro Flash (`pro-flash.md`); the latter is 5 generations at ≤96px versus MCP `inpaint_image` at 10 for a small square canvas | Select the controls, mask behavior and approved price needed for the edit; do not confuse base REST with MCP Pro inpaint |
| Palette reduction, clean-up, unzoom | `reduce_colors`/`correct_pixelart`/`unzoom_image` or their REST twins, 0.1 generations — far cheaper than regenerating a bad frame | Never; there is no Pro variant |

When choosing a cheap route, name the tradeoff plainly (cost, candidate variety and possible differences in detail/adherence) and follow `usage-reporting.md` for cost reporting.

If the cheap result misses a required view or instruction, report that failure and propose a fitting reference/control or approved alternative. A Pro label alone does not prove it will fix adherence.
